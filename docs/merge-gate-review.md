# Merge gate deployment review

This records the disposition of the initial automated review before enabling the merge requirement.

- **Base changes after verification:** strict required-status protection must remain enabled, including for administrators. An older PR head then becomes out of date when `main` advances and cannot merge. Updating the branch changes its head and triggers a new status. The publisher also checks both head and base before reporting success. Do not disable strict protection.
- **Official-statement-only PRs:** these are the separate problem preparation process, and cannot be required to prove a candidate that is not registered yet. They receive an explicit no-candidate-change result, never a proof-pass claim. Changes to any statement referenced by an existing submission do select that submission and fail the immutable trusted-statement prerequisite. Adding a new candidate together with its own statement also fails. Independent approval is checked against the protected-base reviewer roster, which is currently empty.
- **Backend regression workflow:** this is ordinary unprivileged PR CI for changes to the implementation, using an ephemeral GitHub-hosted runner and read-only permissions. It is not the authority for the `lean-verification` commit status. The latter runs only protected-base code with separate publishing jobs. Testing proposed infrastructure necessarily tests its proposed code; its success alone never approves a candidate proof. Repository writers and infrastructure maintainers remain trusted roles.
- **System package drift:** the Debian build stage uses a dated signed snapshot, and Ubuntu pins every installed package to the successful run's exact version in `ubuntu-packages.lock`, including transitive dependencies. The build compares the complete installed inventory against this lock and fails on any difference or unavailable version. Snapshot metadata expiry is disabled for the historical archive only; package signatures remain required. The fixed base image digests, snapshot date, package lock, final package inventory, executable hashes, and runtime image ID bind the environment. Snapshot changes require new backend tests. See [Debian snapshot usage](https://snapshot.debian.org/#usage). The Ubuntu snapshot endpoint returned HTTP 503 during validation; the exact-version lock avoids depending on that endpoint without permitting version drift.
- **Resolver failure:** a resolver/API outage may leave the required status missing or pending. This is intentionally non-passing and blocks merge. The workflow failure is visible in Actions; rerun from current `main` after resolving the outage. A fallback must not guess a head or reuse a previous success. Only resolved exact-head results are published.
- **Superseded backend runs:** a concurrency group now cancels older runs for the same ref.
- **Process tracing:** the local seccomp profile removes every allow rule for `ptrace` and `process_vm_*`, in addition to separate container PID namespaces for builds and checkers.
- **Toolchain evidence drift:** a regression test checks the recorded source commits, release, and archive checksum against the build recipe and exporter setup. Runtime executable hashes and package inventories provide additional evidence.
